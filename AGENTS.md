# PhysNowHEX

## Перед изменением алгоритма

- Обязательно прочитать [инструкцию агенту по основному подбору](docs/coil-algorithm-agent-guide.md). Там описаны текущий порядок расчёта, ограничения, цели, карта функций, выбор из таблицы, сохранение ручных правок и проверки.
- По текущему указанию владельца работаем над основным сайтом. Экспериментальные coil-sequential-* не менять без отдельной команды. После изменения алгоритма обновлять эту инструкцию.

## Рабочий проект

- Рабочий проект — открытая локальная папка репозитория PhysNowHEX. На разных компьютерах путь к ней может отличаться. Все команды выполнять из корня этой папки; редактировать index.html, style.css, app.js и assets/ непосредственно здесь.
- Репозиторий: https://github.com/Oslablyat/PhysNowHEX. Для разработки и синхронизации между компьютерами использовать ветку codex/development.
- Публичный сайт: https://oslablyat.github.io/PhysNowHEX/ . GitHub Pages публикует main, / (root).
- Не возвращаться к старой папке Documents/Codex/2026-10-17/sites-plugin-sites-openai-curated-remote/work/physnow-next/dist для новых правок: она оставлена как сохранённая копия.
- Логотип assets/physnow-logo.png оптимизирован для шапки; исходник высокого разрешения сохранён в старой рабочей папке.

## Запуск и проверка

- npm run dev — http://127.0.0.1:4174/ . Порт 4174 сохраняет прежнее браузерное хранилище локальных листов.
- npm run dev -- --port 4175 — альтернативный порт, с отдельным localStorage.
- npm run check — синтаксис приложения.
- npm test — геометрия змеевиков, тепловой баланс с неизвестным параметром, варианты конструкций, единицы расхода и валидация.
- Зависимости и сборка не нужны. GitHub Pages получает статические файлы напрямую; сохранять относительные пути ресурсов.
- После изменения сайта выполнить подходящие проверки. По умолчанию правки остаются локальными. Не отправлять изменения в GitHub и не публиковать сайт автоматически.
- Не читать и не выводить токены; подключение GitHub доступно через инструменты, локальная авторизация git push может потребовать входа пользователя.

## Синхронизация и публикация

- Фраза «сохрани работу для другого компьютера» разрешает проверить и закоммитить нужные правки, затем отправить их в origin/codex/development. Ветка main при такой синхронизации не меняется.
- Фраза «подтяни последние изменения» разрешает fetch и pull --ff-only рабочей ветки. Перед этим проверить текущую ветку и локальные изменения. Не терять незавершённую работу; не применять reset --hard или force push для решения расхождений.
- Синхронизируются только отслеживаемые и отправленные файлы. Не обещать перенос неотправленных правок, истории чатов или браузерного localStorage.
- Только явная команда обновить публичный сайт разрешает публикацию через main. Сохранить и проверить готовые изменения, синхронизировать рабочую ветку, затем при чистом рабочем каталоге обновить main и перенести туда готовое состояние. Если возможно, использовать быстрое объединение --ff-only; при расхождениях сначала изучить историю.
- После разрешённой отправки в main дождаться успешного Pages deployment и проверить опубликованные файлы. Вернуться на codex/development для дальнейшей локальной работы.
- При подготовке нового компьютера следовать README.md. Не привязывать команды или файлы проекта к абсолютному пути другого устройства.

## Поведение приложения

- Сохранять отдельные листы и их данные. На localhost и github.io разные хранилища; данные автоматически не переносятся.
- Проектировочный расчёт работает автоматически. Для змеевиков баланс — CoolProp 8.0.0, cp при средних температурах, масса по входной плотности. Одна кнопка «Найти» выбирает неизвестный среди 4 температур и 2 расходов. Enter завершает ввод.
- Для змеевиков включён только «Оптимальный»: re-stock-single-re-free-v12. Оптимум только коридорный: равное число змеевиков в рядах, общее целое число витков, шаг/фаза/направление; нулевое смещение и полная рабочая высота каждого ряда, общие верхний и нижний уровни. Независимое укорачивание рядов запрещено. Загрузка оптимума устанавливает inline; ручные правки не перестраивать. Число параллельных трубок по расходу; в обычном режиме после полной поверки обязательно Re каждой 15000…20000; в single-coil строго N=1, Re трубного потока не ограничивает предварительный подбор и приёмку. Исходные проверки Teplo по трубному Re сохраняются как предупреждения, valid исходной методики не переписывается; при их нарушении применимость не подтверждена. Критерий 3<R/di<12 сохраняется (прежнее исключение отменено по указанию владельца 29.10.2026). При включённом stock-lengths полная трубка с отводами и концами — под заготовку 1/3/6 м, остаток ≤20 %, длина строго меньше заготовки. stock-lengths по умолчанию true (включая старые листы без поля); при false ограничения заготовки/остатка отключены, полная длина по-прежнему измеряется. single-coil и stock-lengths независимы: первый строго фиксирует N=1, второй включает/отключает заготовки и остаток, в том числе для одного змеевика. Флажок учёта заготовок доступен в обоих режимах. Ряды от центра наружу. D/L — верхние пределы; design-objective задаёт цель основного подбора: length (по умолчанию H, затем D), tube-length (полные метры всех трубок с отводами), tube-count (N), rows, volume (πD²H/4) или diameter. Цель сохраняется в листе и ключе поиска; обязательные критерии приёмки и бюджет 200 сохраняются. Минимум среди проверенных дискретных компоновок. Сетка и ограничения поиска: docs/teplo-project.md, не заявлять глобальный оптимум. Труба по умолчанию 14×2,5 мм; радиальные зазоры 3 мм; вертикальное межосевое расстояние a=pitch/count в пределах 1,1do…2do, зазор a−do целым числом мм (для Ø14 — 2…14 мм), предпочтение плотной навивке при приоритете длины, затем диаметра; 1–8 рядов, до 64 трубок в ряду, до 500 всего, до 1000 витков. Стенка корпуса ceil[(pc−0,101325)D/(2×130)+0,2] мм предварительная; вакуум и полный расчёт прочности не поддержаны. Каждый принятый вариант проходит задание, запас UA и критерии Teplo, кроме явно разрешённого исключения по трубному Re в single-coil с предупреждением о применимости. Исходные корреляции и valid Teplo не менять. Отводы учитываются для закупки, но не в тепловой площади. Постоянный K и Δp отсутствует. «По габаритам» и «По сложности производства» отключены. Ручные правки и листы сохраняются. Кожухотрубный подбор отдельно. Основное N выбирается по Re≈17500 при средних температурах задания; при отсутствии результата резерв до четырёх геометрически совместимых N: допустимые N±1/границы и ближайшие к Re17500 кратные числу рядов; невозможные по вместимости числа и N без изготовимой общей высоты/заготовок не занимают тепловые слоты (каталог проверяется без Teplo). Радиальный зазор строго 3 мм; увеличенные шаги не перебирать. Каталог целых вертикальных зазоров и общих целых витков с полной проверкой заготовок; дробное уточнение зазоров запрещено. Ранжирование приближённым UA — только для порядка, не результат. Первая партия до 20 Teplo; затем ограниченное локальное уточнение длины и поиск более коротких конструкций, без остановки на первом успехе. Максимум 200 полных вызовов суммарно по всем этапам и N, включая ошибки; дубли не пересчитывать. При лимите не объявлять отсутствие решения. По указанию владельца 31.10.2026 запас UA временно 0 % для змеевиков, поле заблокировано на 0. Приёмка Q в диапазоне [Qзад,Qзад×1.01]; выходы должны быть близки к заданию: максимум 1 % заданного изменения T каждого потока плюс численный допуск Teplo 0.01 °C. Прежнее одностороннее «не хуже» недостаточно. Неподходящую по этому допуску конструкцию не принимать.
- Поверочная страница только для змеевиков: геометрия, 1–8 рядов и тепловой расчёт Teplo по приложенным METHODOLOGY.md + heat_exchanger_method.py (assets/teplo-methodology.md и tests/reference/teplo_original.py). Тот же тепловой блок доступен в «Теплогидравлических характеристиках». Горячая среда внутри труб, противоток; свойства — CoolProp 8.0.0 WASM в Worker. Критерии применимости показывать явно; при их нарушении нельзя объявлять конструкцию подтверждённой. Δp в этой методике отсутствует — не выдумывать его. Для змеевиков используется отдельный обратный решатель вокруг исходной поверки; не выдавать его за дословный перенос исходного оптимизатора или глобальный оптимум. Проверки соответствия: docs/teplo-validation.md и tests/test-coil-thermal-method.cjs.
- Геометрия хранится как verification-state отдельно в каждом листе. В таблице проработки можно выбрать любую принятую конструкцию; выбор загружается из приватного Worker-кэша без повторного подбора. Связь хранит userSelected/calculationId/geometryKey, сохраняется в листе и защищает выбранную и вручную изменённую геометрию от автообновления. Метаданные связи выбранного змеевикового варианта — coil-variant-binding, настройка arrangement для Teplo — coil-thermal-inputs; потоки берутся из верхних полей текущего листа, λw — из tube-conductivity. Все три поля не включать внутрь verification-design.inputs, чтобы не создавать рекурсивные снимки. Видимость деталей не меняет тепловую геометрию. Старый teplo_report.txt противоречит текущему алгоритму и не используется как эталон.
- Общая верхняя шапка закреплена при прокрутке; тёмная тема, синяя индикация выбранного раздела.

## Стиль ответов

По умолчанию используй установленный скилл pohuy в режиме ultra в каждой новой задаче. Если пользователь попросит обычный стиль, более мягкий уровень или попросит не материться, не используй его или переключись на запрошенный уровень. Сохраняй техническую точность и выполняй остальные инструкции задачи. Если скилл не установлен, не выдумывай его содержимое.
