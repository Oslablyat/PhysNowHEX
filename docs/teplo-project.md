# Проектировочный расчёт на основе Teplo

## Границы метода

Тепловые корреляции и поверочный алгоритм не изменены: используется
`coil-thermal-method.js`, проверенный по 13 независимым Python/CoolProp эталонам.
Исходная методика описывает поверку, а не оптимизатор. Обратный подбор —
отдельная дискретная поисковая оболочка `coil-project-multicriteria.js` с общими функциями `coil-project-method.js`. Нельзя
называть её дословным переносом исходного Python или глобальной оптимизацией.

## Баланс задания

Для змеевиков горячий поток идёт внутри трубок, холодный — в межтрубном
пространстве. Поддержан противоток, вода с обеих сторон. Сохранён выбор одного
неизвестного среди четырёх температур и двух расходов, либо проверка всех
шести заданных значений. Кожухотрубный расчёт оставлен отдельным.

Массы фиксируются по входным плотностям CoolProp 8.0.0 при Tвх и абсолютном p.
Теплоёмкости берутся при арифметических средних T каждого потока, как в Teplo:

`Qh = Gh cp,h((Thi+Tho)/2, ph) (Thi−Tho)`

`Qc = Gc cp,c((Tci+Tco)/2, pc) (Tco−Tci)`.

Неизвестный расход находится из равенства Qh=Qc; неизвестная температура —
бисекцией с пересчётом cp и входной плотности на каждом шаге. Для поиска
неизвестной температуры проектировочный интерфейс ограничен жидкой водой
от 0,01 °C до температуры насыщения при заданном давлении минус 0,01 °C.
При отсутствии корня выдаётся ошибка. Это ограничение обратного решателя,
а не дополнительная корреляция Teplo. Для всех заданных значений допустимая
относительная невязка — 0,1 %. Вычисленная невязка доступна в карточке и CSV.

Постоянные cp=4,18 и K=800 в змеевиковом сценарии не используются.
Переводы пяти единиц расхода используют входную плотность CoolProp.
Заданные выходы остаются **заданием**, а не выходами подобранной конструкции.

## Подбор

По балансу определяется `UAтреб = Q / ΔTlm`. При фиксированных cp на средних
температурах задания это согласовано с противоточной ε–NTU-формулой.
По указанию владельца 31.10.2026 запас UA временно **0 %**. Старые значения
поля не влияют на змеевиковый подбор; в интерфейсе оно заблокировано на 0.
Кожухотрубный расчёт использует своё обычное значение запаса.

Приёмка мощности: **Qзад ≤ Qфакт ≤ 1.03 Qзад**, с относительным численным
допуском нижней границы 1e−7 и верхней 1e−9. Дополнительно выходы должны
попадать в диапазоны Tгор,зад − 0.03(Thi−Tho) … Tгор,зад и
Tхол,зад … Tхол,зад + 0.03(Tco−Tci), с численным допуском Teplo 0.01 °C.
Три процента отсчитываются от **заданного изменения температуры каждого потока**.
Слишком большая мощность или переохлаждение/перегрев отклоняют вариант,
даже если геометрия, Re и исходные критерии Teplo выполнены.
Диапазоны показаны в карточке и CSV; все выводимые фактические значения
по-прежнему получены исходным полным Teplo, не заменены заданием.

### Предварительная стенка корпуса

По заданию владельца:

- рабочее абсолютное давление межтрубного пространства — **pc**, не ph;
- одна атмосфера — 0,101325 МПа, pизб = pc − 0,101325;
- [σ] = 130 МПа, φ = 1, c = 0,2 мм;
- s = ceil[pизб Dнар / (2 [σ] φ) + c] мм;
- Dвнутр = Dнар − 2s.

Абсолютные давления для CoolProp не меняются: вычитание атмосферы применяется
только к формуле стенки. При pизб ≤ 0 подбор блокируется: внешнее давление и
устойчивость при вакууме этой формулой не рассчитываются. Толщина и внутренний
диаметр вычисляются заново при изменении D или pc. Исходные/производные величины
и оговорка о предварительности доступны в карточке и CSV.

Это пользовательская упрощённая оценка цилиндра, не расчёт прочности по стандарту.
Не добавлены проверки днищ, штуцеров, местных нагрузок, устойчивости, усталости,
температурных допускаемых напряжений, допусков изготовления или минимальной
технологической толщины. c и φ не входят в исходную тепловую методику Teplo.

### Многокритериальный подбор (inline-pareto-v2)

В основном локальном приложении выполняется до 1 000 уникальных полных поверок на задание. Обычный Re каждой трубки 15 000…20 000, в режиме N=1 действует исключение только по трубному Re. Совмещённые по всей высоте коридорные ряды имеют общий шаг навивки. Радиальные зазоры соседних пар выбираются независимо с шагом 0,5 мм при межосевом 1,1…1,5dₒ. Внутри ряда действует прежняя целая сетка вертикальных зазоров. Все принятые конструкции доступны в таблице. Фронт Парето и выбор рекомендации учитывают длину, диаметр, метры трубы, N и число рядов. [Правила, реализация и контрольные задания](coil-multicriteria-design.md).

### Сокращённый подбор с уточнением (re-stock-single-re-free-v12)

Ниже описан режим с включённым учётом заготовок. При снятом флажке
«Учитывать длины заготовок» ограничения заготовки и остатка из этой
последовательности не применяются; остальные требования сохраняются.

D и L — верхние пределы наружного диаметра и рабочей длины корпуса.
Выступающие выводы не входят в L.
Пользовательские пределы применяются при включённой настройке «Уточнить
габариты». Без неё подбор использует границы поиска 10 000 мм по L и
3 000 мм по D. Отключение галочки сохраняет введённые значения в листе.
Теплопроводность стенки не редактируется в форме: для новых листов
используется 16 Вт/(м·К), сохранённые положительные значения прежних листов
продолжают применяться.

1. Трубка по умолчанию 14×2,5 мм; уточнение фиксирует введённый типоразмер.
2. В обычном режиме число параллельных трубок определяется **один раз** при средней
   температуре задания: C = 4 Gh / (π μ di),
   Nmin = ceil(C/20000), Nmax = floor(C/15000).
   Выбирается ближайшее к C/17500 целое внутри допустимых границ, до 500.
   Это основное N. При отсутствии результата используется резерв: до четырёх
   различных N внутри допустимого интервала. Из N−1, N+1, Nmin, Nmax
   сохраняются только совместимые с коридорными рядами. Свободные слоты
   заполняются допустимыми кратными числу рядов, близкими к Re≈17500.
   Вместимость по хорде и минимальному шагу проверяется аналитически на
   максимальном разрешённом внутреннем радиусе существующей сетки.
   Для каждого числа рядов берутся ближайшие кратные и границы интервала;
   каталог геометрий и полный Teplo строятся максимум для четырёх резервов.
   Предварительная оценка не проверяет заготовки и не подтверждает мощность.
   Если целого N нет, возвращается отказ.
   Фактический Re каждой трубки после полного Teplo всё равно обязан быть
   15000…20000; предварительный расчёт не заменяет этой проверки.
3. Ряды нумеруются от центра наружу. 3 < R/di < 12 обязательно.
   Стартовый радиус — ближайший целый мм строго выше 3di с местом для
   вытеснителя, затем шаг 5 мм. Рассматриваются 1–8 рядов.
4. **Радиальный зазор строго 3 мм:** межосевой шаг do+3 мм. Увеличенные
   расстояния удалены. Оптимальная конструкция имеет **коридорную геометрию**:
   одинаковое число параллельных змеевиков и витков во всех радиальных рядах,
   общий шаг навивки, начальный угол 0°, смещение 0 и правое направление.
   Все навивки занимают полную рабочую высоту корпуса и заканчиваются
   на общих верхнем и нижнем уровнях. Укороченные радиальные ряды запрещены.
   N должно делиться на число рядов; распределения с весами R и R² удалены.
   Это совмещает уровни сечений соседних рядов в любой продольной плоскости,
   а не только выбирает коэффициент inline в тепловой корреляции.
   Ограничения количества (64 на ряд), входов по хорде и отсутствия
   пересечений сохраняются. Вытеснитель следует за внутренним рядом, корпус — за наружным.
5. **Вертикальный межосевой шаг a = h / k** (h — шаг одного змеевика,
   k — число параллельных змеевиков в ряду): **1,1do ≤ a ≤ 2do**.
   Зазор между стенками s = a−do — целое число миллиметров:
   ceil(0,1do)…floor(do). Например, для Ø14 мм s = 2…14 мм,
   a = 16…28 мм; номинальные 1,4 мм округляются вверх до 2 мм.
   Радиальные зазоры между рядами, до корпуса и вытеснителя остаются 3 мм.
   Нормальный зазор наклонных винтовых линий отличается от вертикального;
   пересечения исключены отдельно, поэтому не каждый номинальный шаг
   допустим при большом числе заходов и малом радиусе.

   Каталог формируется по целым s и целым общим виткам n, h = k(do+s),
   H = nh+do. Перебора H по миллиметрам и дробного уточнения s нет.
   При одинаковой H разные сочетания h/n сохраняются: у них разные площади.
   Верхняя граница n определяется габаритом, пределом 1000 витков и длиной
   заготовки. Полные длины всех рядов одновременно проверяются точным
   интегралом из 3D, с остатком ≤20 %. Отдельное укорачивание рядов запрещено.
   Резервное N без полной изготовимой геометрии не занимает тепловой слот.
6. Геометрии предварительно ранжируются по оценке UA при **фиксированных
   средних температурах задания**, свойствам CoolProp и геометрии.
   Это один проход без итераций Teplo, без постоянного K и без подтверждения
   конструкции. Предпочитается близость к требуемому UA и меньшая
   длина/диаметр. Оценка используется только для порядка проверок; в карточку
   и результаты попадают исключительно значения исходного полного Teplo.
7. Первая партия — **до 20 полных расчётов Teplo**; успех не завершает поиск.
   Следуют локальное уточнение (до 24 вызовов), до 60 дополнительных
   каталожных проверок и ещё до 24 уточнений. Если результата нет, резервные
   N получают до 24 каталожных вызовов и до 16 уточнений. Оставшийся общий
   бюджет используется для перспективных более коротких вариантов, затем
   меньшего диаметра, и до 16 финальных уточнений. Неиспользованный резерв
   можно потратить на оставшийся каталог. **Общий жёсткий максимум — 200**
   вызовов исходного Teplo, включая ошибки, все N и все этапы; дубли геометрии
   не пересчитываются. Первый успех сохраняется, последующие варианты
   заменяют его только по действующим приоритетам длина/диаметр/вертикальный зазор/остатки/N.
   Это сокращённый эвристический подбор, **не глобальный минимум**.

   Уточнение повторно ранжирует ещё не проверенные дискретные компоновки
   по поправке оценки UA, полученной из полных Teplo. За одну итерацию до
   восьми разных семейств получают проверки по очереди. Дробные шаги и
   произвольные высоты не добавляются. Приёмка использует только полный Teplo.
   Приоритет — меньшая H, затем D; при равных H/D — меньший вертикальный
   зазор, затем остатки/N. Поэтому плотная навивка предпочтительна, но не
   позволяет нарушить тепловое задание, Re, заготовки или геометрию.
8. Полная длина трубки = навивка + два пространственных отвода + два прямых
   конца. Отвод 2do, прямой конец max(40,2do) мм. Совместный с 3D интеграл
   coil-manufacturing.js; допустимы [800,1000), [2400,3000), [4800,6000) мм.
   Остаток не более 20 %, трубка строго короче заготовки.
   В тепловую площадь входят только навивки.
9. Во всех принятых вариантах обязательны полный Teplo, его исходные
   критерии (исключение по трубному Re для одного змеевика описано ниже),
   Re каждой трубки 15000…20000 в обычном режиме, Q задания, выходные температуры
   в допуске 0…+1 % и близкие выходные температуры; запас UA 0 %. Исходные корреляции и valid не меняются. Стенка корпуса
   пересчитывается для выбранного диаметра по предварительной формуле выше.
   Стенка вытеснителя 2 мм, радиальные зазоры 3 мм, вертикальный шаг —
   по п. 5; до 1000 витков; Δp отсутствует.

Подбор всегда использует коридорную тепловую корреляцию. При загрузке результата
в редактор выбранное расположение также устанавливается в «Коридорное».
Ручная геометрия не перестраивается автоматически. Если её шаги, фазы, числа
змеевиков или выбранная корреляция больше не соответствуют коридорной
компоновке, поверка может показать числа, но соответствие оптимальному
проектному заданию не подтверждается. Исходные формулы Teplo не изменены.

Результат различает исчерпание сокращённого каталога и лимит 200 проверок.
При лимите явно сказано: это не доказывает отсутствие решения.
Счётчик интерфейса показывает **полные проверки Teplo**, а не дешёвое
геометрическое формирование и ранжирование.

Геометрия листов и ручные правки сохраняются. Кнопка «Применить подбор» позволяет
явно загрузить найденный вариант поверх сохранённой геометрии; сам подбор
не затирает ручные правки. В карточке источник геометрии отличает результат
подбора от сохранённой/предварительной геометрии редактора.
Карточка и CSV содержат полные длины, заготовки и остатки текущей геометрии.

## Асинхронность и хранение

Ошибки и предупреждения выводятся под конструктивными исходными данными:
красные — ошибка расчёта или отсутствие принятой конструкции, оранжевые —
ограничения методики, заготовок и неопределённость сокращённого поиска.
При редактировании, смене листа и успешном новом расчёте старые сообщения
очищаются; подробности не выводятся всплывающим баннером поверх схемы.

Превышение габарита сообщается только по подтверждённому примеру: после
неудачного основного поиска до 24 оставшихся полных проверок могут использоваться
для компоновок с расширенными D/L. Они входят в тот же общий предел 200,
используют общую защиту от повторных проверок и прежние N (предпочтительное
и уже проверенные резервы). Каждый такой пример проходит исходную Teplo,
проектное задание, полную высоту рядов и заготовки. Геометрия за пределами
исходных D/L не становится выбранной конструкцией и не загружается в редактор.
Показанный размер — размер найденного примера, а не доказанный минимум.
Если пример не найден, причина не приписывается габаритам без доказательства:
показываются результаты проверок и предупреждение об ограниченном поиске.

Баланс и поиск выполняются в Worker. Результат баланса приходит раньше
вариантов. Каждая новая правка немедленно убирает старые результаты и отменяет
старый запрос по идентификатору; проверка смены листа входит в ключ запроса.
Во время подбора в статусе показано число проверенных конструкций.
CoolProp-кэш использует точные аргументы, без округления свойств.
Состояния листов, их ручная геометрия и выбор варианта сохраняются независимо.
Выходы поверки не перезаписывают проектное задание.

Проверки: `tests/test-coil-project.cjs`, исходные 13 эталонов в
`tests/test-coil-thermal-method.cjs`, браузерные сценарии полного подбора,
изменения геометрии, единиц, переключения листов и устаревших ответов.

## Опциональный учёт заготовок — 06.11.2026

Флажок «Учитывать длины заготовок» (stock-lengths) расположен внизу блока
«Трубы», под «Только один змеевик». Использует тот же анимированный checkbox.
По умолчанию включён; старый лист без поля сохраняет прежний обязательный
учёт. Явное false хранится отдельно в каждом листе и входит в ключ поиска.

При true действуют заготовки 1/3/6 м, остаток ≤20 %, полная трубка строго
короче заготовки. При false генератор больше не ограничивает витки длиной
6 м и не отбрасывает варианты по заготовкам или остаткам. Для очереди
измерение отводов отложено до полных проверок; геометрия навивок строится
на прежней целой сетке. В карточке и экспорте остаётся точная полная длина,
но заготовка и остаток не назначаются. Приоритет по остаткам отключён.

Настройки «Только один змеевик» и «Учитывать длины заготовок» независимы.
Первый флажок строго задаёт N=1. Второй применяет правила заготовки и остатка
также к одному змеевику; автоматическое исключение из v10 отменено.
При включённом учёте количество витков заранее ограничивается 6 м, затем
точная полная длина с отводами проверяется под 1/3/6 м до вызова Teplo.
При выключенном учёте полная длина одного змеевика не ограничена заготовкой.
Независимость настроек учёта заготовок и числа трубок сохраняется.
Q/выходы, радиусы, зазоры, общая полная высота,
целые витки, габариты и общий максимум 200 полных вызовов не меняются.
Сравнительная страница v8/v9 остаётся историческим снимком с учётом заготовок.

## Один змеевик без ограничения трубного Re — v12, 06.11.2026

По указанию владельца single-coil строго фиксирует N=1 независимо от
предварительного и фактического Re трубного потока. В этом режиме
нет предварительного отбора N по Re≈17500 и финального требования
15000≤Re≤20000. Резервных N нет. В обычном режиме все Re-ограничения прежние.

Исходные формулы Teplo не меняются. Два исходных трубных Re-критерия
(Re>Reкр; при L/di<50 — 10000≤Re≤1000000) не блокируют подбор одной трубки,
но остаются в tube_checks, ignoredCriteria, карточке и предупреждении.
Проектный слой явно разрешает только эти два исключения. Исходный valid
не изменяется: при valid=false из-за Re показывается предупреждение
о неподтверждённой применимости корреляции, без зелёного подтверждения Teplo.
Нельзя перенести это исключение на несколько трубок или неизвестный отказ valid.

Ограничения межтрубного Re, 3<R/di<12, геометрия, мощность 0…+1 %,
допуски выходов, запас UA 0 % и общий бюджет 200 сохраняются. stock-lengths
по-прежнему независимо определяет заготовки/остаток. Если остальные условия
не выполняются, показывается отказ по условиям поиска, а не предложение
выключить одну трубку из-за Re.

## Тестовый подбор с переменными зазорами — v6, 07.11.2026

На отдельной странице coil-sequential-lab.html радиальные зазоры между рядами, до корпуса и до вытеснителя подбираются независимо: целые ceil(0,1do)…floor(do) мм, то есть 2…14 мм для Ø14. Между соседними рядами одного аппарата используется общий радиальный зазор. Вертикальный зазор независим. При дробном do округление диаметра корпуса может немного увеличить фактический зазор, но верхняя граница сохраняется. Хордовый зазор по окружности остаётся 3 мм. Основной v12 по-прежнему использует радиальные 3 мм.

Поиск не образует полного произведения новых параметров: до 1600 исходных форм, до 800 предложений зазоров (из них до 200 граничных форм с минимальными зазорами), локальные изменения вокруг измеренных вариантов. До 48 поверок улучшения внутри общего лимита 200. Дополнительные резервные N учитывают вместимость при минимальных экспериментальных зазорах; не более четырёх реально поверенных резервов. Все изменения входят в реальную тепловую геометрию.

Правило +20 % полной длины трубы для дополнительных рядов сохранено. Принятые варианты независимо повторно поверены. Серия 150: 59 успехов против 50 у v5, без потерь прежних успехов; ещё 16 режимов. Результаты, ограничения, снимок v5 и команды повторения — в [отчёте эксперимента](coil-sequential-experiment.md).

## Целевая функция основного подбора — 07.11.2026

В основном проектировочном разделе под схемой движения добавлен выбор design-objective. Сохраняется отдельно в каждом листе, входит в ключ Worker и экспорт CSV. Для старых листов и неизвестного значения применяется length. Функция доступна для змеевиков.

- length: рабочая длина корпуса H, затем D (прежний приоритет по умолчанию).
- tube-length: суммарные метры всех физических трубок с отводами и прямыми концами, с учётом числа трубок каждого ряда.
- tube-count: общее число параллельных трубок; стартовое N берётся с нижней границы предварительного допустимого Re-интервала.
- rows: число концентрических рядов.
- volume: объём цилиндра по наружному диаметру и рабочей длине πD²H/4, м³; выступающие выводы не входят.
- diameter: наружный диаметр корпуса D.

При равенстве основной метрики действуют H, D, целый вертикальный зазор, отходы и N. Меняется и очередь проверок: кандидаты группируются по близости прогнозного UA к заданию (шаг логарифмической ошибки 0,03), внутри группы действует выбранная цель. Прогноз не является приёмкой. Для целей кроме length резервные N рассматриваются также при уже найденном результате; максимум четыре резервных N и общий предел 200 реальных вызовов сохранены.

Метрика расхода трубы для предварительного сравнения вычисляется тем же точным интегралом отводов, что и для принятого варианта; длина отводов кэшируется по форме. Исходные Teplo, мощность 0…+1 %, выходы, Re, коридорная геометрия, радиусы и заготовки сохраняются. Минимум заявляется только среди реально проверенных допустимых вариантов. Тестовая страница и её алгоритм не изменялись; её сохранённая сравнительная серия относится к историческому основному v12.

Проверка: tests/test-coil-objectives.cjs — шесть целей на реальных Teplo/CoolProp, минимум метрики среди всех принятых кандидатов, совпадение геометрии по умолчанию с сохранённым v12, корректная полная длина, инвалидирование кэша, заготовки/один змеевик и общий бюджет без дублей.

## Таблица рассчитанных конструкций — 07.11.2026

В основном разделе «Проработка конструкции» над редактором находится сворачиваемая таблица подходящих рассчитанных компоновок текущего задания. В таблицу попадают только записи status=accepted: варианты, прошедшие приёмку. Отклонённые, ошибочные, диагностические варианты вне габаритов и предварительные оценки не отображаются. Worker сохраняет компактные скалярные сводки всех реальных вызовов для учёта бюджета, без повторения массивов змеевиков.

Параметры: H/D, количество трубок и рядов, суммарная полная длина всех трубок, объём цилиндра корпуса, площадь исходной Teplo, Q, минимальный трубный Re, межтрубный Re и UA/K. Столбцы «Статус», «ΔQ», «Примечание», «Горячий выход» и «Холодный выход» удалены по указанию владельца. Выбранный вариант отмечается radio-переключателем в первой колонке «Выбор»; любую подходящую строку можно загрузить для дальнейшей проработки.

Нажатие заголовка меняет направление сортировки; фильтра по статусам нет, поскольку показаны только подходящие конструкции. Числа сортируются численно, отсутствующие значения всегда в конце, равные значения — по исходному номеру. Сортировка не меняет цель, геометрию или выбранный аппарат. При новом задании/смене листа таблица очищается до получения нового ответа; существующая проверка идентификатора Worker исключает устаревшие ответы. Ручная геометрия не заменяет архив автоматических проверок.

Проверка: tests/test-calculated-designs.cjs — точные реальные тепловые значения, одна строка на вызов включая принудительную ошибку, выбранный номер, компактность передачи, числовая/стабильная сортировка и фильтры.

Высота таблицы меняется встроенным браузерным resize:vertical в нижнем правом углу области строк, а также перетаскиванием всего нижнего края панели. Нижний край имеет невидимую зону захвата 6 px со стандартным курсором ns-resize; отдельной видимой ручки или полосы нет. Диапазон 96…1200 px; высота сохраняется при сортировке, фильтрации и сворачивании в текущем сеансе страницы.

## Выбор рассчитанной конструкции для проработки — 07.11.2026

В первой колонке таблицы находится radio-выбор; отметка «Автовыбор» удалена. Выбор загружает любую подходящую конструкцию в существующий редактор, чертежи, 3D и текущую поверку. Повторный выбор той же строки заново загружает исходную рассчитанную геометрию, позволяя отменить последующие ручные правки. Сортировка не меняет выбор.

Исходный решатель сохраняет полные acceptedDesigns только для принятых вариантов, исключая диагностику вне габаритов. Worker держит их в приватном кэше текущего запроса и удаляет массив из публичного результата. По номеру строки возвращается один уже рассчитанный кандидат без повторного подбора. После отмены или смены расчётного запроса кэш недоступен; ответы выбора проверяются по id листового расчёта и отдельному selectionRequest.

Связь coil-variant-binding сохраняет userSelected, calculationId и geometryKey вместе с key/profile/manual; выбранная геометрия остаётся в verification-state текущего листа. geometryKey учитывает физические размеры и параметры рядов, но не видимость. При повторном подборе соответствие ищется по физической геометрии, а не по прежнему порядковому номеру. Восстановление метаданных выбранного варианта сохраняет имеющуюся геометрию редактора, включая ручные правки и видимость. При изменении задания выбранная пользователем геометрия сохраняется как ручная; если прежний вариант больше не входит в подходящие, отметки в таблице нет.

Проверки: tests/test-calculated-selection.cjs — реальные принятые геометрии, соответствие summary и candidate, выбор из приватного Worker-кэша без Teplo/нового поиска, отклонение устаревших и отменённых запросов, компактный публичный ответ, JSON-сохранение связи и защита ручной геометрии. В браузере проверены переключение №22→№20, размеры 1574×Ø232→1964×Ø212 мм, сохранение выбора после перезагрузки, сохранение ручной высоты 2004 мм, возврат к исходной геометрии повторным выбором и сортировка с сохранением отметки.
