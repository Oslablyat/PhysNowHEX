# Подключение методики Teplo

## Что реализовано

Поверочный тепловой расчёт заданной сборки: по геометрии, двум входным
температурам, давлениям и расходам находятся выходы, Q, α, Nu, Re, K и UA.
Горячая среда внутри труб; все змеевики соединены параллельно с равным
массовым расходом. Межтрубная сторона имеет одно минимальное свободное
сечение и одну корреляцию теплоотдачи. Схема — только противоток.

Перенос выполнен по METHODOLOGY.md и heat_exchanger_method.py из Teplo.zip.
Сохранённый TXT и ранние формулировки в Word не являются численным эталоном:
различия перечислены в tests/reference/README.md. Полное описание исходного
алгоритма сохранено в assets/teplo-methodology.md, исходный Python — в
tests/reference/teplo_original.py. Свойства рассчитываются настоящим CoolProp
8.0.0 (WASM), без табличной интерполяции свойств или постоянных cp и K.

## Соответствие алгоритма

| Этап | Реализация и проверка |
| --- | --- |
| Входные расходы | Масса определяется один раз по входной плотности при T и p; при изменении средней температуры масса сохраняется. Есть проверка эквивалентности массового и объёмного ввода. |
| Геометрия | L=n√((2πR)²+h²), di=do−2δ, dm=(do+di)/2, F=πdmL. Целые N и n; h≥Ndo; положительные зазоры к кожуху/вытеснителю; неперекрывающиеся радиальные зоны. Геометрические ошибки блокируют расчёт. |
| Межтрубное сечение | Одна кольцевая полоса 2πRdo на радиальный ряд, без умножения на число змеевиков; Ac — минимум по рядам. |
| Поправки | εφ по таблице; εL — линейная интерполяция сначала по L/di, затем по Re. εr учитывает первую и вторую трубки в порядке обтекания N·n; εb осредняется по F. s1 — средняя разность радиусов, s2 — средний шаг навивки. |
| Свойства | CoolProp 8.0.0 при средних температурах потоков и текущей стенке, давление абсолютное. |
| Трубная теплоотдача | Отдельные Nu, Re и α каждого змеевика. В K подставляется только α, осреднённая по F. Среднего Nu нет. |
| Межтрубная теплоотдача | При Re<1000 — 0,56Re^0,5Pr^0,36; от 1000 — коридорная 0,26Re^0,65Pr^0,33 или шахматная 0,41Re^0,6Pr^0,33, с поправками. Единые Nu и α для аппарата. |
| Стенка и K | Цилиндрическое сопротивление стенки для каждого диаметра, K по среднему диаметру, UA=ΣKiFi. Температуры обеих поверхностей стенки с отношениями площадей dm/do и dm/di. |
| Выходы | Устойчивая противоточная ε–NTU-формула, включая равные водные эквиваленты. Нет выдуманного температурного профиля по рядам. |
| Сходимость | Внешняя итерация средних температур, внутренняя итерация стенки; предел 200/200, допуск 0,01 °C по стенке и обоим выходам. Отсутствие сходимости блокирует вывод. |
| Применимость | Reh>Recr; 3<R/di<12; Rec<100000; диапазон таблицы длины. Число при нарушении сохраняется, статус явно предупреждает об экстраполяции. |

Все 13 эталонов проверяются командой `node tests/test-coil-thermal-method.cjs`
и входят в `npm test`. Допуск: max(1e−7 абсолютный, 1e−9 относительный).
Проверяются не только выходы, но также свойства, площади, поправки, α, Nu,
Re, K, UA, тепловой баланс и статусы. Исходные данные не мутируют.

Ошибка обратного баланса передаётся из Worker с этапом, кодом, проблемными полями
и подсказкой. Невозможная температура включает вычисленный допустимый диапазон.
Над схемой показывается `role=alert`, под найденным полем — видимая подпись;
подсветка не требует blur и работает для read-only неизвестного. При исправлении
или смене листа снимаются подсветка, подпись и aria-invalid. Ошибка загрузки,
ошибка баланса и ошибка подбора различаются; неполный новый лист не вызывает
большого красного сообщения. Проверки: `tests/test-calculation-feedback.cjs`,
сценарий невозможного баланса в `tests/test-coil-project.cjs` и браузерная проверка
150→60 °C, горячий расход 100 кг/с, холодный 30,3344156798 кг/с, pc=0,4 МПа,
неизвестный Tco; затем восстановление при холодном расходе 500 кг/с.

## Границы интеграции

- Интерфейс: «Теплогидравлические характеристики» в проработке конструкции и
  тепловой блок на поверочной странице. Входные потоки автоматически берутся из
  верхних исходных данных текущего листа; горячий/холодный поток сопоставляется
  по температурной роли, а не по старым подписям пространств. При прямотоке или
  выборе неподдерживаемой среды расчёт блокируется с пояснением. Дублирующих полей
  потоков нет. λw задаётся явно рядом с материалом трубы в верхнем блоке; марка
  материала не подменяет численное λw. Прежнее отдельное значение λw мигрирует
  в верхнее поле. В coil-thermal-inputs теперь сохраняется только arrangement.
- Карточка змеевикового аппарата показывает текущую геометрию редактора, а не
  исходный кандидат, и полный результат Teplo: общие величины, свойства сред,
  межтрубные параметры, все ряды и каждый змеевик. Открытие карточки запускает
  расчёт даже при скрытом тепловом экране. При изменении исходных данных старые
  результаты немедленно удаляются; открытая карточка обновляется после расчёта.
  Проектные Q/K/F выделены отдельно от поверочных. Параметры карточки ищутся по
  названию, символу или единице, включая «альфа» / alpha и Nusselt.
- Проектировочный баланс змеевиков использует cp при средних температурах и
  входные плотности CoolProp. Реализован последовательный подбор полновысотных
  рядов снаружи внутрь: первая конструкция, выполняющая задание, запас UA и
  неотключённые критерии. По согласованию временно исключено только 3<R/di<12;
  исходные предупреждения и флаги Teplo не меняются. Принятие с исключением
  не означает полной применимости. Постоянный K исключён из этого сценария.
  Обратный решатель — расширение вокруг исходной поверки, не часть исходного
  Python и не глобальный оптимизатор. Подробности: [teplo-project.md](teplo-project.md).
- Геометрический подбор теперь использует целое число витков. Ручные полувитки
  не удаляются, но поверочная методика требует целого числа и выдаёт ошибку.
- Тепловая поверхность подбора и поверки берётся по среднему диаметру; геометрия
  дополнительно сохраняет наружную поверхность для размеров/объёмов и 3D.
- Редактор сайта использует один типоразмер труб для всех рядов. Расчётное ядро,
  как и эталон, поддерживает различные диаметры рядов; это проверяется тестами.
- Применяются также более строгие геометрические проверки редактора. В частности,
  вытеснитель должен покрывать всю высоту навивок для модели кольцевого канала.
- Видимость деталей и рядов в 3D не меняет расчёт. Подводящие отводы не учитываются
  в поверхности, как и в приложенном коде. Два цикла вычисляются в Worker, не в 3D.
- Методика не задаёт потери давления: Δp не выдумывается. Стенка корпуса отдельно
  предварительно оценивается по пользовательской формуле с [σ]=130 МПа, φ=1,
  c=0,2 мм и pизб=pc−0,101325 МПа; это не часть исходного Teplo и не полный
  расчёт прочности. Проверяются округление вверх, pc вместо ph, внутренний
  диаметр, зазоры, целые полновысотные витки и остановка на первом варианте.
  Нет полного расчёта прочности,
  загрязнения, изменения фаз, технологичности и локальных температурных графиков.
