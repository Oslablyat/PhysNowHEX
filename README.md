# PhysNowHEX

PhysNow — рабочее пространство для предварительного расчёта теплообменников и редактирования геометрии змеевиков.

## Проектировочный подбор змеевиков по Teplo

Сейчас включён только вариант «Оптимальная конструкция». «По габаритам» и
«По сложности производства» временно отключены. Вместо прежнего общего
перебора применяется последовательное добавление полновысотных рядов внутрь.

В новых расчётах по умолчанию выбран змеевиковый тип. Старые листы сохраняют свой тип и данные. Баланс решается по CoolProp (cp при средних температурах, массы по плотностям на входе), каждый шаг геометрии проверяется Teplo. Принимается первое выполнение задания, запаса UA и неотключённых критериев. По согласованию владельца временно исключено только `3 < R/di < 12`; исходные предупреждения и `valid=false` Teplo сохраняются. Полная применимость методики не подтверждается. Постоянный K, гидравлическая строка и Δp не используются.

При фиксированных D и L стенка предварительно оценивается как `ceil[(pc−0,101325)D/(2×130×1)+0,2]` мм: pc — абсолютное рабочее межтрубное давление в МПа, D — наружный диаметр в мм. Это заданная упрощённая формула, не полноценный расчёт прочности; вакуум не проверяется. По умолчанию труба 14×2,5 мм, первый диаметр навивки `Dвнутр−20` мм. Ряды по одному змеевику добавляются внутрь с радиальным зазором 3 мм. Целые витки занимают всю рабочую высоту; межвитковый нормальный зазор не менее 3 мм. Вытеснитель рассчитывается по внутреннему ряду с зазором 3 мм. Пределы редактора: 1–8 рядов, до 1000 витков. Это первый достаточный вариант в заданной последовательности, не глобальный оптимум. Площадь по среднему диаметру и длина не включают отводы; L ограничивает рабочую высоту, не выступающие выводы.

Нажатие строки сразу загружает её полную геометрию в «Проработку конструкции» и 3D. Дополнительная кнопка подтверждения для змеевиков не нужна. Ручные правки помечаются, сохраняются с листом и не теряются при перезагрузке; повторное нажатие строки восстанавливает исходный вариант. Новое задание потоков, UA, L, D или типоразмера заново запускает подбор. Ручная геометрия при этом не затирается. Устройство обратного решателя, границы и проверки описаны в [docs/teplo-project.md](docs/teplo-project.md). Старую геометрию без метаданных связи сохраняем как ручную до явного выбора строки. Метаданные связи хранятся отдельно от `verification-state` и не входят в `verification-design.inputs`.

## Две ветки

| Ветка | Назначение |
| --- | --- |
| `codex/development` | Разработка и перенос работы между компьютерами. Отправка в эту ветку не обновляет публичный сайт. |
| `main` | Опубликованная версия. GitHub Pages публикует корень этой ветки. Обновлять только по явной команде владельца. |

Локальное сохранение файла не отправляет изменения в GitHub. Перенос между компьютерами происходит после `commit` и `push` на первом устройстве и `pull` на втором.

## Начать на другом компьютере

Нужны Git и поддерживаемая LTS-версия Node.js с npm. Папка проекта может находиться в любом удобном месте.

```sh
git clone --branch codex/development https://github.com/Oslablyat/PhysNowHEX.git
cd PhysNowHEX
git config --local pull.ff only
git config --local push.default simple
npm run dev
```

Откройте папку `PhysNowHEX` как локальный проект в Codex. Инструкции из `AGENTS.md` будут доступны вместе с файлами проекта. Для коммитов настройте имя и email автора Git, для отправки изменений — авторизацию GitHub на этом компьютере. Codex может помочь с этой настройкой; файлы с токенами в репозитории не нужны.

Устанавливать зависимости и выполнять сборку не нужно. Адрес локального сайта: [http://127.0.0.1:4174/](http://127.0.0.1:4174/).

Если порт занят:

```sh
npm run dev -- --port 4175
```

Альтернативный адрес: [http://127.0.0.1:4175/](http://127.0.0.1:4175/). Для остановки своего сервера нажмите `Ctrl+C` в терминале.

## Продолжить работу на другом устройстве

Перед началом работы:

```sh
git switch codex/development
git status --short
git pull --ff-only
```

Если есть незавершённые правки или Git сообщает о расхождении истории, сначала разберите их. Не используйте принудительное обновление или сброс локальных файлов для синхронизации.

После завершения работы:

```sh
npm run check
npm test
git status --short
git diff
git add -- <нужные-файлы>
git commit -m "Describe the change"
git push
```

`<нужные-файлы>` — место для списка проверенных файлов, которые нужно перенести. Не вводите этот заполнитель буквально. На рабочей ветке `git push` отправляет изменения в `origin/codex/development`.

Вместо ручных команд можно попросить Codex:

- «Сохрани работу для другого компьютера» — проверить правки, сохранить их коммитом и отправить в рабочую ветку.
- «Подтяни последние изменения» — получить изменения рабочей ветки без потери локальных правок.
- «Обнови сайт на GitHub» — отдельно опубликовать готовую версию через `main` и проверить GitHub Pages.

Несохранённые и неотправленные изменения доступны только на том компьютере, где они сделаны. Перед переключением устройства завершайте передачу работы; при параллельном редактировании одних файлов потребуется объединение изменений.

## Публикация по отдельной команде

Публикуйте только после проверки изменений и явной команды владельца. Сначала сохраните и синхронизируйте готовую рабочую ветку, затем при чистом рабочем каталоге:

```sh
git fetch origin
git switch main
git pull --ff-only origin main
git merge --ff-only codex/development
git push origin main
git switch codex/development
```

Если быстрое объединение невозможно, сначала изучите расхождения. Не используйте `force push` или `reset --hard`. После отправки в `main` дождитесь успешного выполнения `pages build and deployment` в GitHub Actions и проверьте опубликованный сайт.

## Расчётные данные

Листы расчёта хранятся в `localStorage` браузера. Git переносит исходники проекта; расчётные листы и история чатов Codex в эти файлы не входят.

На разных устройствах и в разных браузерах свои листы. Адреса `localhost`, `127.0.0.1`, разные порты и опубликованный сайт также используют отдельные хранилища. Для прежних локальных листов сохраняйте адрес `http://127.0.0.1:4174/`.

Поверочная страница и раздел «Теплогидравлические характеристики» содержат тепловой расчёт Teplo: по геометрии и входным потокам вычисляются выходные температуры, Q, α, Nu, Re, K и UA. Свойства — CoolProp 8.0.0 в локальном WASM Worker. Входные потоки Teplo автоматически берутся из верхних исходных данных текущего листа; λw задаётся явно рядом с материалом трубы; горячая сторона — внутри труб, схема — противоток. Методика и проверка соответствия описаны в [docs/teplo-validation.md](docs/teplo-validation.md). Гидравлические потери не рассчитываются: формул Δp в приложенной методике нет. Проектировочный режим добавляет обратный дискретный поиск вокруг исходной поверки Teplo; это отдельное расширение, а не исходный алгоритм оптимизации.
