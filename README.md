# PhysNowHEX

PhysNow — рабочее пространство для предварительного расчёта теплообменников и редактирования геометрии змеевиков.

[Инструкция агенту: как устроен основной подбор и где менять его правила](docs/coil-algorithm-agent-guide.md).

## Проектировочный подбор змеевиков по Teplo

Версия v12 подбирает коридорную геометрию на полную высоту: равное число
змеевиков и витков в рядах, общий шаг, фаза, направление, верхний и нижний
уровни. Каждый ряд занимает всю рабочую высоту; независимое укорачивание
рядов запрещено. [Проверка полной высоты v8](docs/audits/full-height-v8.md).
[Историческая серия v8/v9](docs/audits/coil-gap-v8-v9.md): 53 → 43 конструкции; из 41 общего успешного задания 37 аппаратов стали короче. На сравнительной странице доступны исходные данные, две 3D-модели, параметры рядов и заготовки.

[Тестовый алгоритм v6 с переменными зазорами](docs/coil-sequential-experiment.md) подбирает независимо зазоры между рядами, до корпуса и до вытеснителя: для Ø14 мм — целые 2…14 мм. Вертикальный зазор подбирается отдельно. Локальные изменения и граничные формы заменяют полный перебор сочетаний; лимит 200 полных Teplo сохранён. Правило разумного выбора прежнее: дополнительные ряды при росте полной длины трубок не более 20 % к найденной простой компоновке. Доступны четыре поверенных профиля и фактические зазоры в таблице. Повторная серия 150 заданий: найдено 59 против 50 у тестового v5 и 43 у основного; прежние 50 сохранены, новых 9. Полных Teplo 7218 против 6415 и 13304; максимум 200. Среди общих успехов с v5 корпус короче в 30 случаях, длиннее в 2. Ещё проверены 16 режимов. Основной подбор не заменён. [Открыть тестовую страницу](http://127.0.0.1:4174/assets/coil-sequential-lab.html#normal-free-0.5).

В исторической серии v6 из 150 заданий найдено 55 конструкций, пересчитанных Python.
[Проверка коридорной геометрии и данные v6](docs/audits/coil-inline-v6.md).
В v7 резерв N учитывает вместимость коридорных рядов; исправлен пропуск
56 трубок при холодном входе 31 °C. Подробности: [разбор отказов](docs/audits/inline-counts-v7-diagnosis.md).
Архивное [сравнение v4/v5](docs/audits/coil-selection-v4-v5.md) относится к
подбору до введения этого геометрического условия.

В основном проектировочном расчёте доступна «Целевая функция»: минимум длины корпуса (по умолчанию), метров трубы с отводами, количества трубок, рядов, объёма цилиндра корпуса или диаметра. Цель сохраняется в каждом листе и влияет на очередь проверок и выбор результата. Подробности — [методика подбора](docs/teplo-project.md). Сейчас включён только вариант «Оптимальная конструкция». Число параллельных трубок определяется по расходу; в обычном режиме итоговый Re каждой трубки 15000…20000 обязателен. В режиме «Только один змеевик» N=1 независимо от Re трубного потока; нарушения исходных Re-критериев Teplo остаются видимыми предупреждениями о применимости. Ограничение 3 < R/di < 12 сохраняется во всех режимах. При включённом «Учитывать длины заготовок» полная трубка с отводами выбирается под заготовку 1/3/6 м с остатком ≤20 %. Флажок по умолчанию включён; при выключении снимаются ограничения заготовки и остатка, включая предел 6 м. Это независимая настройка: для одного змеевика учёт заготовок также можно включать и выключать. Ряды от центра наружу. D/L — верхние пределы; выбор по целевой функции среди проверенных дискретных компоновок, по умолчанию сначала рабочая длина, затем диаметр. Не глобальный оптимум; подробная сетка поиска и ограничения — в [docs/teplo-project.md](docs/teplo-project.md). Основное N определяется по Re≈17500; при отказе пробуются до четырёх резервных N внутри допустимого интервала. Увеличенные межрядные зазоры и глобальный проход длины по мм удалены. После первых 20 проверок выполняются локальное уточнение длины и поиск более короткого корпуса; первый успех не завершает поиск. Общий предел — 200 полных вызовов по всем этапам и N, включая ошибки; отсутствие результата в этом лимите не доказывает отсутствие решения. В тестовом режиме запас UA 0 %, приёмка мощности от задания до +1 % с контролем близости выходных температур.

Труба по умолчанию 14×2,5 мм, радиальные зазоры 3 мм; вертикальный межосевой шаг 1,1…2d, зазор целым числом мм (для Ø14 — 2…14 мм); 1–8 рядов. Стенка предварительно ceil[(pc−0,101325)D/(2×130)+0,2] мм; вакуум и полный расчёт прочности не поддержаны. Площадь Teplo включает только навивку, закупочная длина включает отводы и концы. Рабочая длина корпуса не включает выступающие выводы. Баланс и все принятые варианты проверяются Teplo/CoolProp; постоянный K и Δp не используются.

Автоматический результат загружается в «Проработку конструкции» и 3D. Ручная геометрия и данные листов сохраняются отдельно и не затираются подбором. Новая версия алгоритма обновляет связь автоматической геометрии. Метаданные хранятся отдельно от verification-state и не вкладываются в verification-design.inputs.

Если баланс не имеет решения, поле выделяется сразу, даже если оно только для чтения; под ним показывается только «Проверьте значение». Большого блока над схемой нет. Подробная причина доступна при наведении на поле, в доступном описании и статусе расчёта. При ошибке не показываются старые тепловые результаты, экспорт блокируется. После изменения данных или перехода на другой лист подсветка и подпись снимаются и рассчитываются заново.

| Ветка | Назначение |
| --- | --- |
| `codex/development` | Разработка и перенос работы между компьютерами. Отправка в эту ветку не обновляет публичный сайт. |

Локальное сохранение файла не отправляет изменения в GitHub. Перенос между компьютерами происходит после `commit` и `push` на первом устройстве и `pull` на втором.

## Начать на другом компьютере

Нужны Git и поддерживаемая LTS-версия Node.js с npm. Папка проекта может находиться в любом удобном месте.

```sh
git clone --branch codex/development https://github.com/Oslablyat/PhysNowHEX.git
cd PhysNowHEX
git config --local pull.ff only
git config --local push.default simple
npm run dev
```

Откройте папку `PhysNowHEX` как локальный проект в Codex. Инструкции из `AGENTS.md` будут доступны вместе с файлами проекта. Для коммитов настройте имя и email автора Git, для отправки изменений — авторизацию GitHub на этом компьютере. Codex может помочь с этой настройкой; файлы с токенами в репозитории не нужны.

Устанавливать зависимости и выполнять сборку не нужно. Адрес локального сайта: [http://127.0.0.1:4174/](http://127.0.0.1:4174/).

Если порт занят:

```sh
npm run dev -- --port 4175
```

Альтернативный адрес: [http://127.0.0.1:4175/](http://127.0.0.1:4175/). Для остановки своего сервера нажмите `Ctrl+C` в терминале.

## Продолжить работу на другом устройстве

Перед началом работы:

```sh
git switch codex/development
git status --short
git pull --ff-only
```

Если есть незавершённые правки или Git сообщает о расхождении истории, сначала разберите их. Не используйте принудительное обновление или сброс локальных файлов для синхронизации.

После завершения работы:

```sh
npm run check
npm test
git status --short
git diff
git add -- <нужные-файлы>
git commit -m "Describe the change"
git push
```

`<нужные-файлы>` — место для списка проверенных файлов, которые нужно перенести. Не вводите этот заполнитель буквально. На рабочей ветке `git push` отправляет изменения в `origin/codex/development`.

Вместо ручных команд можно попросить Codex:

- «Сохрани работу для другого компьютера» — проверить правки, сохранить их коммитом и отправить в рабочую ветку.
- «Подтяни последние изменения» — получить изменения рабочей ветки без потери локальных правок.
- «Обнови сайт на GitHub» — отдельно опубликовать готовую версию через `main` и проверить GitHub Pages.

Несохранённые и неотправленные изменения доступны только на том компьютере, где они сделаны. Перед переключением устройства завершайте передачу работы; при параллельном редактировании одних файлов потребуется объединение изменений.

## Публикация по отдельной команде

Публикуйте только после проверки изменений и явной команды владельца. Сначала сохраните и синхронизируйте готовую рабочую ветку, затем при чистом рабочем каталоге:

```sh
git fetch origin
git switch main
git pull --ff-only origin main
git merge --ff-only codex/development
git push origin main
git switch codex/development
```

Если быстрое объединение невозможно, сначала изучите расхождения. Не используйте `force push` или `reset --hard`. После отправки в `main` дождитесь успешного выполнения `pages build and deployment` в GitHub Actions и проверьте опубликованный сайт.

## Расчётные данные

Листы расчёта хранятся в `localStorage` браузера. Git переносит исходники проекта; расчётные листы и история чатов Codex в эти файлы не входят.

На разных устройствах и в разных браузерах свои листы. Адреса `localhost`, `127.0.0.1`, разные порты и опубликованный сайт также используют отдельные хранилища. Для прежних локальных листов сохраняйте адрес `http://127.0.0.1:4174/`.

Поверочная страница и раздел «Теплогидравлические характеристики» содержат тепловой расчёт Teplo: по геометрии и входным потокам вычисляются выходные температуры, Q, α, Nu, Re, K и UA. Свойства — CoolProp 8.0.0 в локальном WASM Worker. Входные потоки Teplo автоматически берутся из верхних исходных данных текущего листа; λw задаётся явно рядом с материалом трубы; горячая сторона — внутри труб, схема — противоток. Методика и проверка соответствия описаны в [docs/teplo-validation.md](docs/teplo-validation.md). Гидравлические потери не рассчитываются: формул Δp в приложенной методике нет. Проектировочный режим добавляет обратный дискретный поиск вокруг исходной поверки Teplo; это отдельное расширение, а не исходный алгоритм оптимизации.

### Обновить данные страницы испытаний

После сохранения полных отчётов v8/v9 выполните `node tests/build-coil-audit-comparison.cjs`. Команда сохраняет облегчённые данные в `assets/coil-audit-data.json`; геометрии и тепловые результаты копируются без изменений. `node tests/test-coil-audit-comparison.cjs` проверяет хеши источников и все 150 пар. Страница работает со снимком испытаний от 05.11.2026 и не запускает подбор заново.

Для лаборатории последовательного подбора: `node tests/audit-coil-sequential.cjs`, `node tests/audit-coil-sequential-focused.cjs`, затем `node tests/report-coil-sequential.cjs`. Первый скрипт заново запускает оба алгоритма на прежней сетке 150 заданий и сохраняет подробный отчёт и данные страницы; второй обновляет описание результатов. `node tests/test-coil-sequential.cjs` проверяет сам поиск и аналитические интервалы витков, `node tests/test-coil-sequential-lab.cjs` — все пары и хеши исходников. На странице можно просматривать сохранённую серию и отдельно пересчитывать свои условия. Основные листы и localStorage она не меняет.
